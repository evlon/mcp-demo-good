# mcp-demo-good

一个**会好好说话**的 MCP 演示服务。

配合 [`mcp-demo-bad`](https://www.npmjs.com/package/mcp-demo-bad) 使用，
用来演示一件事：**同样的功能，描述写得清不清楚，用户敢不敢点。**

---

## 它和坏版的区别

| | 本包（good） | mcp-demo-bad |
|---|---|---|
| 工具功能 | **完全一样** | **完全一样** |
| 工具名/参数 | **完全一样** | **完全一样** |
| 工具描述 | 说清动什么、能不能撤、影响范围 | 只写"处理一下" |
| 成功返回 | 说清改了哪一项、别的有没有事、怎么恢复 | 只有一个"完成" |
| 失败返回 | 说清哪里错、该怎么办 | "操作失败，请联系管理员" |

**两个包可以同时装**，用工具开关面板切换对比。

---

## 怎么装

### 方法一：npx（推荐，不用预装）

在 DSH 里加一个 MCP 服务：

```
名称：demo-good
命令：npx
参数：-y mcp-demo-good
```

坏版同理：改成 `mcp-demo-bad`，名称改成 `demo-bad`。

### 方法二：全局安装

```bash
npm install -g mcp-demo-good
```

然后 MCP 配置里：
```
命令：mcp-demo-good
```

---

## 它提供什么工具

三个工具，覆盖三种副作用等级（两版一致）：

| 工具 | 副作用 | 干什么 |
|---|---|---|
| `read_status` | 只读 | 读系统状态快照，不改任何数据 |
| `write_config` | **有副作用** | 改一条配置，立即生效，旧值无法自动回滚 |
| `send_report` | **对外发送** | 发一份报告给指定人，**发出无法撤回** |

**都是演示用，不会真改你的系统、也不会真发消息。**

---

## 装好后怎么用

装完在会话里说：

```
帮我把超时改成 60 秒
```

模型会调用 `write_config`，然后返回：

```
已修改配置项「timeout.seconds」
- 新值：60（立即生效）
- 原值已被覆盖，无法自动恢复；如需恢复请重新设置回原值
- 其他配置项未受影响
```

**换成坏版再做一次，你会看到它只回你一个"完成"。**

---

## 这个包想说明什么

一个能让人放心的工具描述，要回答四个问题：

1. **它动什么**（哪个配置项？发给谁？）
2. **动完能不能撤**
3. **会不会牵连别的数据**
4. **出错时怎么办**

本包（good）四条都写了，坏版一条都没写。

**这就是为什么用户面对两个功能完全一样的工具，只敢点其中一个。**

## 协议说明

- stdio 传输，JSON-RPC 2.0，按行分隔（NDJSON）
- 支持协议版本 `2025-11-25` 和 `2026-07-28`
- 工具名会被宿主改写成 `mcp__<你配的服务名>__<工具名>`
- 日志走 stderr，stdout 只走协议消息
